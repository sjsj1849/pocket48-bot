# X 网页登录与监控会话

管理面板的「浏览器」页提供「X 登录」和「同步 X 登录态」。

1. 点击「X 登录」，连接远程桌面并打开 X 的真实网页登录页。
2. 在下方网页输入邮箱，按 X 提示完成邮箱验证码、密码或其他账号验证。
3. 成功进入 X 后点击「同步 X 登录态」。不完整的验证流程不能同步。

同步仅将 X 的 `auth_token` 和 `ct0` 保存到服务器的 `storage/x/session.json`，目录权限为 0700，文件权限为 0600；面板只返回是否配置及保存时间。不会收集或保存网页中输入的邮箱密码，也不会把 Cookie 广播到浏览器侧卡的其他连接。

浏览器会复用已有 X 标签页，清理闲置标签时保留 X 的登录、验证与首页标签。X 请求不经过为小红书配置的代理，使用服务器的直接网络连接。

「会话已保存」表示已保存必需的 Cookie。是否可以采集时间线需要采集器另行验证；这个登录入口本身不会启动 X 监控，也不会发送历史帖子到 QQ。

现有邮箱中转可以辅助获取验证码，但不能替代 X 的网页验证流程。邮箱服务限流或中转未覆盖对应邮箱时，可从原邮箱手动填入最新验证码。

## 自动邮箱验证码登录

`deploy/agently-x-login.service` 启动自动登录任务，依赖既有 Agently 邮箱中转、浏览器侧卡和 Python 采集环境。账号信息由管理员临时写入私有 `storage/x/login-input.json`，不进入 Git；自动流程完成后删除密码与验证码文件，仅保留邮箱地址和会话。

任务首先验证邮箱可读。上游接口 429 时等待共享的指数退避，确认可读之后才请求新验证码。取码期间暂停后台监听，完成后恢复；仅接受来自 X、收件人匹配指定账号且在本次请求后收到的验证码。旧邮件、其他账号和歧义验证码不能使用。

自动登录状态显示在浏览器页。上游未解除限流时不宣称邮箱恢复或 X 已登录；出现额外网页验证时保留页面。保存会话之后的采集测试是只读用户查询，不发送 QQ 消息。

采集依赖版本固定在 `sidecar/x-monitor/requirements.txt` 和 `requirements.lock`。`collector.py` 提供有界用户查询、搜索和时间线读取；安装环境与保存会话本身不代表 X 转发服务已经运行。
