# X 帖子监控：开源选型与 BOT 接入设计

调研日期：2026-09-13。本文是源码调研与接入设计，尚未实现 X 服务，也未用真实 X 登录态验证采集或 QQ 媒体发送。

## 结论与开源选型

建议以 [twscrape](https://github.com/vladkens/twscrape) 为采集依赖，将 X 网页协议留在独立 Python 采集模块；本项目的 Go BOT 负责订阅、持久化去重、消息排版和服务状态。这个判断基于项目当前源码及本 BOT 的结构，不代表第三方接口稳定性已实测。

| 项目 | 已核对的能力 | 对本项目的适用性 |
| --- | --- | --- |
| [twscrape](https://github.com/vladkens/twscrape) | 用户查询、用户搜索、帖子与回复时间线、图片、视频、动图、引用与转帖；保存会话，按账号和接口处理限流；MIT | 首选。账号限流、媒体数据模型较完整，适合长期轮询监控 |
| [Twikit](https://github.com/d60/twikit) | 用户帖子、搜索、媒体、引用与转帖、Cookie 保存与加载；MIT | 备选。适合较轻的单账号采集，仍需 BOT 自己组织运行状态与重试 |
| [Nitter](https://github.com/zedeus/nitter) | 网页前端、RSS；Nim 和 Redis/Valkey；AGPLv3 | 不选为主链路。多维护一个完整前端没有必要，公共实例 RSS 是否开放也不一致 |

Nitter README 还披露了 2026-08-24 收到 X 下架要求，随后宣布项目继续。因此不能把某个公共 Nitter 实例视为长期可靠的监控入口。信息来自其 [README](https://github.com/zedeus/nitter#readme)。

twscrape 当前 [README](https://github.com/vladkens/twscrape#start-with-cookies) 明确要求授权 X 账号，并推荐包含 `auth_token` 和 `ct0` 的浏览器会话。免费网页采集方案并不等于免登录或永不过期；真实账号、服务器网络与可见内容需要单独验证。

## 内容适配

下面是需要实现的 BOT 行为，第三方库负责返回媒体资料，不负责 QQ 转发：

| 内容 | BOT 行为 |
| --- | --- |
| 纯文本、长文本 | 使用完整正文；解码 HTML 实体；展开正文短链接，避免截断长帖 |
| 图片、文本加图片 | 正文后逐张发送，保留媒体顺序；优先原图；原帖链接与时间放在图片后 |
| 视频 | 选择可下载的 MP4 变体，携带封面；下载后通过现有 OneBot 视频消息发送；按实际大小限制处理 |
| 动图 | X 动图通常提供视频资源，以动态媒体处理，不只发静态缩略图 |
| 转帖 | 显示订阅用户转发了谁，带原作者正文和媒体；事件仍按订阅用户的转帖记录去重 |
| 引用帖 | 先显示订阅用户正文，再显示被引用用户及引用内容；明确区分两位作者 |
| 回复 | 可选监控；只转发订阅用户自己的回复，避免把别人回复该用户的内容当作其发帖 |
| 删除、不可访问、未知媒体 | 不推送空白消息；展示有权读取的正文与链接；记录具体异常 |

媒体字段已核对 [twscrape/models.py](https://github.com/vladkens/twscrape/blob/main/twscrape/models.py)：照片为 `media.photos`，视频提供 `thumbnailUrl` 与多个 `variants`，动图提供 `videoUrl`；`retweetedTweet`、`quotedTweet` 和回复标识分别表示不同关系。媒体按类型分组会丢失混合附件的原始顺序，适配器应结合原始响应 `extended_entities.media` 保留顺序。不能把库返回缩略图误认为已获得可发送的视频。

## 面板配置

在「配置」增加 X 平台页，复用现有平台卡片与按钮风格：

- 登录：打开 X 登录页、同步浏览器登录态；服务器浏览器无法登录时支持用户自行导入会话。写入私有存储，GET 接口只返回已配置状态，不回传会话。
- 运行：总开关、检查间隔、可选代理，推荐默认 120 秒；保存后下一轮生效。
- 查找用户：`@用户名`、纯用户名、`x.com/用户名` 和 `twitter.com/用户名` 做精确解析；显示名走用户搜索。结果展示头像、显示名、`@用户名`，并保存数字用户 ID；ID 使用字符串，避免 JavaScript 精度丢失。
- 订阅：目标用户、QQ 群、发帖开关、回复开关、转帖开关、@全体开关；可编辑、暂停、删除。同一个用户可投递至不同群，采集只做一次。
- 只读预览：展示最近匹配内容、媒体类型与消息排版；不发 QQ，不改推送游标。

默认开启普通发帖和引用帖，回复与转帖分别可选。这里的「转发到 QQ」和「目标用户在 X 上的转帖」是两种行为，面板应使用清晰的选项名称。

## 总览与消息格式

启用 X 后总览增加一行 X 服务。运行时间沿用主 BOT 服务的运行时间；单独展示最近检查、最近成功、有效订阅数、最近新增事件数和具体错误。状态区分待登录、待订阅、首次扫描、运行中、限流等待、需要重新登录和扫描异常。存在 Cookie 或进程启动本身不能判为健康，需实际成功读取目标时间线。

普通图文格式：

```text
【显示名|X】
帖子正文

[图片 / 动态媒体]

https://x.com/username/status/帖子ID

2026-09-13 21:00:00
```

视频优先沿用现有 QQ 媒体发送方式；如 OneBot 不接受视频与文字混发，则连续发送内容说明与独立视频消息，并通过实测确定顺序。图片/视频下载或上传失败必须有正文、封面（可用时）及原帖链接作为替代，且不能声称视频已成功送达。

## 与现有代码衔接

本仓库目前没有 X 采集和配置模块。已经核对可借鉴的本地入口：

- `internal/logic/weverse.go`：独立轮询、配置热加载、先持久化基线、按群推送。
- `internal/weverse/store.go`：平台独立存储、原子写入、敏感文件权限。
- `internal/admin/weverse.go` 与 `admin-ui/src/pages/WeverseConfig.tsx`：平台配置、查找目标、编辑订阅、只读预览与浏览器同步。
- `internal/admin/overview.go`：从持久化扫描状态构建服务健康卡片与最近活动。
- `sidecar/weibo-auth/index.mjs`：现有浏览器会话及 WebSocket 命令通道，可增加 X 的打开与同步命令。
- `internal/napcat/models.go`：已有文字、图片、视频、@全体消息段；`internal/logic/media.go` 有媒体缓存。

建议新增 `internal/xmonitor/`、`internal/logic/x.go`、`internal/admin/x.go`、`admin-ui/src/pages/XConfig.tsx` 和 `sidecar/x-monitor/`。平台配置、会话、采集游标、健康状态放在 `storage/x/`，不要把新增会话混入 `config.json`，也不要提交到 Git。

采集模块只开放本机只读用户查询、搜索和时间线操作。固定依赖版本，不向 BOT 暴露库的发帖、私信、关注等写操作。HTTP 或子进程输出都需限制大小并返回结构化错误；Cookie 不应出现在命令行、日志或错误响应中。

## 运行规则与验证要求

首次订阅只建立基线，不补发历史；重启读取已保存状态。不能用列表第一条或单一时间戳判断新帖：置顶、旧帖新转发及乱序结果都可能影响时间线顺序。按事件 ID 去重，保留轮询重叠范围，直到遇到已知记录；超过分页上限报告无法完整覆盖，而不是默默推进游标。

每个用户的错误单独记录，防止一个不可读账号阻塞其他账号。限流尊重重置时间，网络异常有限重试、指数退避，登录失效停止反复请求。twscrape 默认可能一直等待可用账号，接入时需显式设置账号等待策略与整个请求超时；接口结构变更需要升级适配，不能靠无限重试修复。

现有 OneBot `SendGroupMessage` 是入队接口，入队不等于 QQ 送达。若新增媒体下载或上传重试逻辑，要处理发送响应与去重之间的关系，避免因失败丢帖或重复整条提醒。

验收包括：真实登录后查找指定用户；纯文本、多图、文字加图、视频、动图、引用、转帖、回复；首次基线与重启去重；限流、登录失效、单用户失败；面板订阅流程；总览真实健康状态；QQ 实际视频和多图送达。当前阶段只完成了源码与结构调研，以上真实采集和发送验收尚未执行。
